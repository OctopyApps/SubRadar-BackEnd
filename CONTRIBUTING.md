# Git-воркфлоу

- В `main` прямой push запрещён — только через Pull Request.
- В `dev` можно пушить напрямую.
- Для фич/фиксов можно заводить отдельную ветку и открывать PR в `dev` или сразу в `main`.
- Когда `dev` готов к релизу — открывается PR `dev` → `main`.

## Тесты

- Прогоняются автоматически на каждый push в `dev` и на каждый PR в `dev`/`main`
  (`.github/workflows/backend-tests.yml`).
- При установке тега `v*` тесты гоняются ещё раз перед сборкой релиза —
  сборка и публикация бинарников (`.github/workflows/BackEndRelease.yml`)
  не запустятся, если тесты не прошли.
- Запустить тесты локально: `tests/RUN_ALL.sh` (см. раздел 8 [README.md](README.md)).

## Релиз

1. Смержить `dev` в `main` через PR.
2. Добавить `docs/ReleaseNotes/vX.Y.Z.md`.
3. Поставить тег `vX.Y.Z` на `main` и запушить — CI прогонит тесты, соберёт
   бинарники под linux/darwin/windows и опубликует GitHub Release.
